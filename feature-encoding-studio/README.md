# Feature Encoding Studio

Four silent, 1920×1080, 30 FPS, H.264 MP4 explainer videos on **Feature Encoding in Machine Learning**
(Label, One-Hot, Ordinal, plus a combined comparison and decision guide), generated with
**TypeScript + React + Remotion**. All visuals are original and drawn by code (SVG, CSS, Canvas).
Math is typeset with KaTeX. There is no audio track and no third-party media.

Author: Nitish Bhardwaj

> **Status honesty note.** The code was type-checked, bundled with Remotion's webpack bundler, and every scene was
> server-rendered at 213 sample frames without errors, and every Python snippet shown in the videos was run against
> scikit-learn 1.8.0. The MP4 files themselves have **not** been rendered yet: they must be rendered on your machine
> (steps below), because rendering needs a headless Chrome download.

## 1. Requirements (Windows + VS Code)

* **Node.js 18 or newer** (20 or 22 LTS recommended). Check with `node -v`.
* **Internet on first run**, so Remotion can download its own headless Chrome (about 100-150 MB, once).
* **FFmpeg is not required.** Remotion 4 ships its own FFmpeg binaries.
* About 4 GB free RAM and a few GB of disk. Rendering about 23 minutes of 1080p video takes a while (see §4).

## 2. Install

Open the folder in VS Code, open a terminal (`Ctrl + ~`) and run:

```
npm install
```

Optional checks:

```
npm run typecheck
```

## 3. Preview before rendering

```
npm run preview
```

Remotion Studio opens in the browser. Pick a composition in the left sidebar (`LabelEncoding`, `OneHotEncoding`,
`OrdinalEncoding`, `Comparison`) and scrub or play the timeline.

## 4. Render the MP4 files

| Command | Output |
|---|---|
| `npm run render:label` | `out/01-label-encoding.mp4` |
| `npm run render:onehot` | `out/02-one-hot-encoding.mp4` |
| `npm run render:ordinal` | `out/03-ordinal-encoding.mp4` |
| `npm run render:comparison` | `out/04-feature-encoding-complete-guide.mp4` |
| `npm run render:all` | all four, one after another |

Every render uses `--codec=h264 --muted` (H.264, no audio track), 1920×1080 at 30 FPS. Remotion creates the `out/`
folder automatically if it is missing. Expect roughly 10-30 minutes per video depending on your CPU. Run one video
first to check the timing on your machine.

## 5. Where the files are

`out/` inside the project folder, for example `feature-encoding-studio\out\01-label-encoding.mp4`.
Right-click a file in the VS Code Explorer and choose **Reveal in File Explorer**.

## 8. Project structure

```
src/
  index.ts            registerRoot
  VideoRoot.tsx       all compositions (4 videos + 3 diagram stills)
  theme.ts            colours, fonts, video size; styles/theme.css is the CSS twin
  anim.ts             time and easing helpers (useSec, prog, lerp, deterministic rand)
  components/
    AnimatedBackground.tsx   grid + network backdrop, Canvas ParticleField
    SceneTransition.tsx      Scene (fade, camera push-in, heading), VideoShell (series + progress bar)
    DatasetTable.tsx         tables that assemble row by row
    CodePanel.tsx            syntax-highlighted Python + output panel
    ComparisonTable.tsx      animated comparison grids
    DecisionTree.tsx         animated decision tree
    GraphAnimation.tsx       NumberLine, Staircase, SparseMatrix
    Pipeline.tsx             animated processing pipeline
    MathBlock.tsx            KaTeX
    AdvLimCards.tsx, ui.tsx  shared cards, callouts, reveals
  videos/             one file per video (scene lists and scene components)
  diagrams/           the three standalone diagrams
  data/examples.ts    shared example data (verified scikit-learn outputs)
python/verify_snippets.py   re-run every snippet shown in the videos
```

To change a scene, edit its component in `src/videos/`. To change a scene's length, change its `dur` (seconds) in the
scene list at the bottom of that file; the composition length updates automatically.

## 9. Educational accuracy notes

* `LabelEncoder` learns `classes_` **alphabetically**. For `["Red","Blue","Green","Red"]` it returns `[2 0 1 2]` with
  `classes_ = ['Blue' 'Green' 'Red']`. The Label video first uses Red=0, Blue=1, Green=2 as an *illustrative* mapping
  and says so, then shows the real output in the Python scene.
* `LabelEncoder` is intended for target labels `y`; `OneHotEncoder` and `OrdinalEncoder` are for input features `X`.
* `OneHotEncoder` orders columns alphabetically too (`color_Blue, color_Green, color_Red`); the hand-built teaching
  tables use Red, Blue, Green order for readability and are labelled as such.
* With `handle_unknown="ignore"`, an unseen category becomes an all-zeros row.
* Claims about model behaviour (linear, distance-based, tree-based) are worded as "may" and "depends on the model".

### Verified outputs (scikit-learn 1.8.0)

Run `python python/verify_snippets.py` (needs `pip install scikit-learn numpy`). The outputs on screen match it.

## 10. Troubleshooting

| Problem | Fix |
|---|---|
| `'npm' is not recognized` | Install Node.js LTS from nodejs.org, then reopen VS Code. |
| Chrome download fails or hangs | Check network/proxy/antivirus; run `npx remotion browser ensure`, then retry. |
| `Error: Could not find Chrome`/browser missing | Run `npx remotion browser ensure`. |
| Render is slow or the PC freezes | Lower parallelism: add `--concurrency=2` to the render command. |
| Out-of-memory / crash on a long render | Close other apps; use `--concurrency=1`. |
| `EPERM`/file in use when overwriting | Close any player that has the MP4 open, then render again. |
| Fonts look different | Videos use Segoe UI and Consolas (installed on Windows). On other systems Remotion falls back to Arial and a monospace font. |
| Port in use when previewing | `npm run preview -- --port=3001`. |
| Want a quick test render | `npx remotion render src/index.ts LabelEncoding out/test.mp4 --frames=0-299 --muted` (first 10 seconds). |

## 13. Short explanation of each method

* **Label encoding** gives every category one integer code. It is compact, and suited to target labels `y`. On nominal
  input features the codes can look like an order or distance that does not exist, which some models may misread.
* **One-hot encoding** gives every category its own binary column. It avoids inventing a ranking, but the column count
  grows with the number of categories, and unseen categories need handling.
* **Ordinal encoding** gives integer codes that follow a meaningful order you define explicitly. It preserves order,
  not necessarily equal distances, and is only appropriate when the order is real.
